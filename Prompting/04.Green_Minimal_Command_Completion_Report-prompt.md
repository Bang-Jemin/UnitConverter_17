문제:
현재 green-minimal Command가 수정 허용 파일을 너무 구체적인 파일명으로 고정하고 있다.
하지만 UnitConverter 프로젝트는 OCP/SRP 구조를 목표로 하므로,
나중에 예외 파일, 기본 단위 등록 파일, formatter 하위 폴더, 설정 로더 파일 등이 추가될 수 있다.
따라서 허용 파일 목록을 고정 파일명 중심이 아니라 계층/책임 중심으로 바꿔줘.

수정 방향:

1. "허용 파일" 섹션을 "허용 범위"로 변경한다.

허용 범위:
- unit_converter/domain/**/*
  - 단위 개념, 단위 등록/조회, 변환 계산, 도메인 예외
- unit_converter/app/**/*
  - 입력 파싱, 출력 포맷, CLI 경계 처리 보조
- unit_converter/infrastructure/**/*
  - 설정 파일 로드, 외부 설정 파싱
- unit_converter/cli.py
  - CLI 진입점 연결
- unit_converter/**/__init__.py
  - 패키지 import 연결

2. 새 파일 생성 규칙을 추가한다.

새 파일 생성 규칙:
- 현재 RED 테스트를 통과하는 데 필요한 경우에만 새 파일을 생성한다.
- 새 파일을 만들 경우, 어떤 테스트 ID 때문에 필요한지 작업 요약에 남긴다.
- 미래 확장을 예상한 빈 추상화 파일은 만들지 않는다.
- 현재 RED 묶음과 무관한 설정 파일, formatter, 동적 등록 기능은 미리 구현하지 않는다.

3. OCP 관련 제한을 강화한다.

OCP 제한:
- 새 단위 추가를 위해 converter 내부에 if/elif 단위 분기를 늘리지 않는다.
- 새 단위는 Registry 등록 또는 설정 파일 로드 방식으로 확장 가능해야 한다.
- 기존 Converter 핵심 로직은 단위 목록을 몰라도 동작하도록 유지한다.
- 단위별 변환 비율은 meter 기준 값으로 표현한다.

4. 수정 금지 파일은 유지한다.

수정 금지:
- UnitConverter.py
- docs/*
- .cursorrules
- .cursor/commands/*
- tests/* 의 기대값
- pyproject.toml

5. GREEN 원칙은 유지한다.

- 현재 RED 테스트 통과가 목적이다.
- 리팩토링 금지.
- 추가 요구사항 선구현 금지.
- 테스트 기대값 변경 금지.
- skip / xfail 금지.
