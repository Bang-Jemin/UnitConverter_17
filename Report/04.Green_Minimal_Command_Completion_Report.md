## 1. 세션 목적

RED 스켈레톤(Report 03) 완료 후 **GREEN 단계**에 사용할 Cursor Command `/green-minimal`을 정의·보완한다.

- 고정 파일명 중심 허용 목록 → **계층·책임 중심 허용 범위**로 전환
- OCP/SRP 확장(예외, 기본 단위, formatter 하위, 설정 로더)을 GREEN 단계에서도 유지
- RED TDD 규칙과 `.cursorrules` GREEN 원칙과 정합

**범위 밖 (본 세션):** GREEN 구현 코드, 테스트 기대값 변경, `UnitConverter.py` 수정

## 2. 배경 · 문제

| 항목 | 내용 |
|------|------|
| 문제 | 기존(또는 예상) green-minimal Command가 `input_parser.py`, `converter.py` 등 **고정 파일명**으로 수정 허용 범위를 제한 |
| 구조 목표 | UnitConverter는 **OCP/SRP** — domain / app / infrastructure 계층 분리 |
| 확장 예시 | `domain/exceptions.py`, `domain/default_units.py`, `app/formatter/`, `infrastructure/yaml_config_loader.py` 등 |
| 요구 | GREEN 단계에서도 **필요 시 새 파일 생성** 가능하되, **최소 구현·OCP 준수** 유지 |

## 3. 산출물

### 3.1 신규 Command

| Command | 파일 | 용도 |
|---------|------|------|
| `/green-minimal` | [.cursor/commands/green-minimal.md](../.cursor/commands/green-minimal.md) | RED 실패 테스트 통과용 **최소 구현** (`unit_converter/`만) |

> **참고:** 작업 시점에 `green-minimal.md`가 존재하지 않아 **신규 작성**되었다. 내용은 사용자 지정 보완 방향을 반영한다.

### 3.2 Command 핵심 구조

| 섹션 | 요약 |
|------|------|
| **허용 범위** | `domain/**/*`, `app/**/*`, `infrastructure/**/*`, `cli.py`, `**/__init__.py` — 책임별 정의 |
| **새 파일 생성 규칙** | 현재 RED 통과에 필요할 때만; Test ID · PRD ID 기록; 빈 추상화·선구현 금지 |
| **OCP 제한** | Converter `if/elif` 단위 분기 금지; Registry/설정 확장; meter 기준 비율; Formatter 분리 |
| **수정 금지** | `UnitConverter.py`, `docs/*`, `.cursorrules`, `.cursor/commands/*`, `tests/*` 기대값, `pyproject.toml` |
| **GREEN 원칙** | 최소 구현, 리팩터 금지, 선구현 금지, skip/xfail/assert 약화 금지 |

### 3.3 허용 범위 상세

| 경로 | 책임 |
|------|------|
| `unit_converter/domain/**/*` | 단위 개념, 등록/조회, 변환 계산, 도메인 예외 |
| `unit_converter/app/**/*` | 입력 파싱, 출력 포맷, CLI 경계 처리 보조 |
| `unit_converter/infrastructure/**/*` | 설정 파일 로드, 외부 설정 파싱 |
| `unit_converter/cli.py` | CLI 진입점 연결 |
| `unit_converter/**/__init__.py` | 패키지 import 연결 |

**판단 기준:** 현재 RED 테스트 통과에 필요하고, 위 책임 중 하나에 명확히 속하는가?
