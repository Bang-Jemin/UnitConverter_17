**새 파일 생성:** 없음 (기존 stub 파일만 구현)

### 3.2 구현 API 계약 (달성)

| 모듈 | 공개 API | 반환·계약 |
|------|----------|-----------|
| `unit_converter.app.input_parser` | `parse(raw: str)` | `(unit: str, value: float)` — 첫 `:` 기준 분리 |
| `unit_converter.domain.unit_registry` | `UnitRegistry.create_default()` | meter/feet/yard 기본 등록 |
| `unit_converter.domain.converter` | `Converter(registry).convert_all(unit, value)` | `dict[str, float]` — 전 단위 변환 |
| `unit_converter.cli` | `handle_input(raw: str)` | `HandleInputResult` — `ok`, `error_kind`, `message`, `output_lines` |

### 3.3 구현 상세 (최소 범위)

**`parse`**
- `raw.split(":", 1)` → unit / value_str 분리
- `float(value_str.split(":", 1)[0])` — 추가 `:` 포함 시 숫자 부분만 파싱 (`meter:2.5:extra` → 2.5)

**`UnitRegistry`**
- `RATIO_FEET_PER_METER = 3.28084`, `RATIO_YARD_PER_METER = 1.09361` — **단일 정의** (Mom Test 상수)
- meter 기준 `meters_per_unit` 등록: meter=1.0, feet=1/3.28084, yard=1/1.09361

**`Converter`**
- 입력 → meter 환산 → Registry 조회로 전 단위 dict 반환
- 단위별 `if/elif` 분기 **없음** (OCP 준수)

**`handle_input`**
- `:` 없음 → `error_kind="format"`
- 숫자 불가 → `error_kind="number"`
- 단위 누락(`:2.5`) → `error_kind="format"`
- 음수 → `error_kind="negative"`, message에 `"negative"` 포함
- 정상 → `convert_all` 결과로 `output_lines` 생성

### 3.4 GREEN 중 수정 이력

| 순서 | 이슈 | 조치 |
|------|------|------|
| 1 | `test_parse_uses_first_colon_only` FAIL — `float("2.5:extra")` ValueError | `value_str.split(":", 1)[0]`로 숫자 부분만 파싱 |
