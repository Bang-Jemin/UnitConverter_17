## STEP 1 — Mom Test 요약

### 페르소나

UnitConverter README 실습에서 **기존 `UnitConverter.py`를 확장·수정하는 유지보수 개발자** (단위 추가, 입력 검증, 테스트 작성 담당).

### Mom Test 증거 (과거·구체)

| # | 질문 관점 | 증거 |
|---|-----------|------|
| 1 | 새 단위 추가 시 수정 범위 | `if/elif`에 넣은 상수와 **28행 출력 계산 상수가 달라** 값이 잘못 나온 적 있음 |
| 2 | 입력 형식·음수 처리 | **음수를 넣으니 에러** 발생 |
| 3 | 하드코딩된 변환 비율 | 여러 곳에서 직접 고친 경험 **없음** — 다만 `3.28084`/`1.09361`이 **4곳에 중복** (19·21·27·28행) |
| 4 | 출력 포맷 확장 | 출력 방식 변경 경험 **없음** — `print` 3줄 + 변환 변수 **한 덩어리** |
| 5 | 테스트 없을 때 회귀 | **테스트가 아직 없음** — 상수 불일치·입력 오류가 자동 차단 불가 |

### 표면 문제 (잘못된 정의 — PRD 본문에 넣지 않음)

- 「OCP/SRP를 만족하는 클래스와 인터페이스가 필요하다」
- 「변환 비율을 JSON/YAML 설정 파일로 빼야 한다」
- 「JSON / CSV / 표 출력 포맷 선택 기능을 넣어야 한다」
- 「pytest로 단위 변환 테스트를 작성해야 한다」
- 「동적으로 `1 cubit = 0.4572 meter`를 등록할 수 있어야 한다」

### 진짜 문제 (한 문장)

**단위 추가나 수정할 때 변환 상수와 출력 계산이 서로 다른 곳에 흩어져 있어, 한쪽만 고치면 틀린 값이 나와도 테스트가 없어 그대로 지나갈 수 있다.**

## STEP 2 — 현재 코드 스냅샷 (`UnitConverter.py`)

| 구간 | 행 | 역할 | Mom Test 리스크 |
|------|-----|------|-----------------|
| 형식 검사 | 4~6 | `:` 없음 거부 | 형식 오류만; 음수 미처리 |
| 파싱 | 8~14 | `split`, `float` | 음수는 `float` 통과 |
| 입력 단위 분기 | 16~24 | `if/elif` + **비율 A** | 단위 추가 시 **touch point 1** |
| 출력 계산 | 26~28 | meter/feet/yard + **비율 B** | **비율 A ≠ B** 시 값 오류 (증거 1) |
| 출력 | 30~32 | `print` 3줄 고정 | 포맷 확장 시 **touch point 2·3** |

README 비율: `1 m = 3.28084 ft`, `1 m = 1.09361 yd` — feet↔yard는 meter 기준.

## STEP 3 — R-G-I-O

### Role

**AI / 개발자**는 UnitConverter를 **유지보수 가능한 제품**으로 다듬는다.

- Mom Test 실수(상수 불일치, 음수 비정상 동작) **재발 방지**
- README 기본·품질·추가 요구를 **변경 비용·회귀 위험** 관점의 요구로 옮김
- 변환·검증·출력·설정·확장의 **책임 경계** 확정

### Goal

| # | 목표 |
|---|------|
| G-01 | README 비율에 따른 **일관된 변환** |
| G-02 | 단위·비율·포맷 추가 시 **수정 범위 최소·예측 가능** (OCP) |
| G-03 | 형식·음수·없는 단위 **예측 가능 처리** |
| G-04 | 수정 후 **자동 회귀 확인** 기준(테스트) |
| G-05 | 설정 외부화·동적 등록·다중 포맷 — **분산·중복 없이** 수용 |

### Input

| 구분 | 내용 |
|------|------|
| **사용자 (CLI)** | `단위:값` — `meter:2.5`, 형식 오류, 음수, 없는 단위 |
| **설정 (정적)** | meter/feet/yard, README 비율, 기본 출력 포맷, JSON/YAML (2차) |
| **확장 (동적)** | `1 cubit = 0.4572 meter` 등록, JSON/CSV/표 포맷 선택 (2차) |

### Output

| 구분 | 내용 |
|------|------|
| **CLI 정상** | 입력 단위 → **전 지원 단위** 변환 줄 출력 |
| **오류** | 형식·숫자·단위·음수·등록 실패 — 변환 **미실행** + 명시 메시지 |
| **포맷 (2차)** | text / JSON / CSV / 표 — **동일 변환 수치**, 표현만 다름 |

### 성공 기준 (테스트로 바꿀 수 있는 문장)

| ID | 기준 |
|----|------|
| SC-1 | `meter:2.5`, `feet:8.2`, `yard:2.7` → README 비율 **허용 오차 내 일치** |
| SC-2 | `meter:-1` → 변환 미실행 + **음수 거부 메시지** |
| SC-3 | `meter:abc`, `meter`, `:2.5`, `mile:1` → **케이스별 오류**, 변환 미실행 |
| SC-4 | cubit 등록 후 **기존 TC 통과** + cubit 출력 |
| SC-5 | text/JSON/CSV/표에서 **동일 변환 값** 추출 가능 |
