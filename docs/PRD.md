## 1. 배경 · 문제 정의

UnitConverter 실습에서 **유지보수 개발자**가 단위·비율·출력을 수정할 때, 같은 정보가 `main()` 여러 지점(`if/elif`, 출력 계산, `print`)에 흩어져 **한쪽만 고치면 틀린 변환 결과**가 나올 수 있다. 현재 저장소에는 **테스트 코드가 없어** 이런 실수가 자동으로 잡히지 않는다.

### Mom Test 증거 (과거 사실)

1. `yard` 추가 시 **`if/elif`에 넣은 상수와 28행 출력 계산 상수가 달라** 값이 잘못 나온 적이 있음
2. **음수 입력**(`meter:-2.5` 등) 시 에러가 발생함
3. 비율을 여러 곳에서 직접 고친 경험은 없으나, `3.28084`/`1.09361`이 **입력·출력에 중복** — 질문 1과 같은 실수 재발 구조
4. 출력 포맷 변경 경험 없음 — `print` 3줄과 변환 변수가 **한 덩어리**로 결합
5. **테스트가 아직 없음** — 수정 후 회귀를 자동 검증할 수 없음

### 표면 문제 (PRD 본문에 넣지 않음)

- 「OCP/SRP 클래스·인터페이스를 만든다」
- 「JSON/YAML 설정 파일로 비율을 빼낸다」
- 「JSON/CSV/표 출력 기능을 넣는다」
- 「pytest로 테스트를 작성한다」

### 진짜 문제 (한 문장)

**단위 추가나 수정할 때 변환 상수와 출력 계산이 서로 다른 곳에 흩어져 있어, 한쪽만 고치면 틀린 값이 나와도 테스트가 없어 그대로 지나갈 수 있다.**

## 3. 범위

### In Scope (1차 — 기본·품질)

- `단위:값` CLI 입력 파싱 및 변환
- 지원 단위: **meter**, **feet**, **yard**
- README 비율 기반 변환 (meter 기준)
- 입력 검증: **음수**, **잘못된 형식**, **없는 단위**
- OCP·SRP를 만족하는 구조로 리팩터
- 단위 변환·입력 검증 **테스트 코드**

### In Scope (2차 — README 추가 요구)

- 변환 비율 **설정 외부화** (JSON/YAML)
- 런타임 단위 등록 (예: `1 cubit = 0.4572 meter`)
- 출력 포맷 선택: **JSON / CSV / 표(텍스트)**

### Out of Scope

- 웹 UI · REST API · DB 연동
- 길이 외 단위(질량, 온도 등)
- 배포·패키징·CI 파이프라인 (본 PRD 범위 밖)

## 6. 출력

### 6.1 CLI 정상 출력

| ID | 요구 |
|----|------|
| OUT-01 | 입력 `값` + `단위` 기준, **지원 모든 단위**로 변환 결과 출력 |
| OUT-02 | 각 줄 형식: `{value} {input_unit} = {converted} {target_unit}` (README 예시) |
| OUT-03 | feet ↔ yard는 **meter 경유** 계산과 일치 |

**예시** (`meter:2.5`):

```
2.5 meter = 2.5 meter
2.5 meter = 8.2 feet
2.5 meter = 2.7 yard
```

### 6.2 오류 출력

| ID | 조건 | 기대 |
|----|------|------|
| ERR-01 | 형식 오류 | 변환 **미실행** + 형식 오류 메시지 |
| ERR-02 | 숫자 파싱 실패 | 변환 **미실행** + 잘못된 숫자 메시지 |
| ERR-03 | 없는 단위 | 변환 **미실행** + 알 수 없는 단위 메시지 |
| ERR-04 | 음수 입력 | 변환 **미실행** + 음수 거부 메시지 (비정상 예외 아님) |
| ERR-05 | 등록 실패 (2차) | 기존 동작 유지 + 등록 실패 사유 |

### 6.3 포맷 출력 (2차)

| ID | 포맷 | 기준 |
|----|------|------|
| FMT-OUT-01 | text | 줄 단위, 사람이 읽기 쉬운 형태 (기본) |
| FMT-OUT-02 | JSON | 동일 변환 결과를 구조화된 필드로 표현 |
| FMT-OUT-03 | CSV | 동일 변환 결과를 행·열로 표현 |
| FMT-OUT-04 | 표 | 동일 변환 결과를 정렬된 표 형태 |

**공통:** 포맷만 바뀌고 **변환 값의 의미·정확도는 동일**해야 한다.
